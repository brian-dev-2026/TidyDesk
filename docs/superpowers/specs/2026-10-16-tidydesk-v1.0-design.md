# TidyDesk v1.0 — Design Spec

Date: 2026-10-16
Status: Approved 2026-10-16
Builds on: `2026-10-16-tidydesk-design.md` (v0.1). Everything there still applies unless this document changes it.

## 1. Goal

Close the product gaps the user picked: auto-update, an exclusions list, a large files finder, an empty folders cleaner, scheduled auto-clean, organizer options, drag & drop, and an error log with export. Also fix the window reset/close glitch. Ship the result as **v1.0.0**, the first public release.

### Success criteria

- An installed TidyDesk finds a newer GitHub Release, downloads it, and offers "Restart to update".
- Nothing under an excluded path is ever listed, moved or deleted, whichever feature acts on it.
- A user can see the biggest files on a drive or in a folder and send chosen ones to the Safe Bin.
- A user can remove empty folders and get them back.
- An opt-in daily or weekly junk clean runs by itself and shows a Windows notification.
- The organizer can sort by date, and users can edit which extensions go into which category.
- Folders can be dropped onto the Organizer, Duplicates, Large Files and Empty Folders pages.
- Errors are written to a log file, and the activity history can be exported as CSV.
- Stray keystrokes such as Ctrl+R and Ctrl+W can no longer reload or close the window.

## 2. Glitch fix (bug)

**Cause under investigation:**
- The app never sets an application menu, so Electron's default menu is active and its accelerators work even though the frameless window hides it.
- **Ctrl+R** reloads the page, which resets it to the Dashboard. **Ctrl+W** closes the window.
- During automated runs the test window can take keyboard focus while the user is typing elsewhere.

**Fix:**
- `Menu.setApplicationMenu(null)` removes the default menu.
- Ctrl+Shift+I for DevTools stays available in dev builds only.

**Proof:** a check in the real app shows that before the fix, Ctrl+R and Ctrl+W reload and close the window, and after the fix they do nothing.

## 3. Auto-update

- **Module:** `electron-updater` in a new `src/main/updater.ts`. It is active only when `app.isPackaged`.
- **Schedule:** checks 10 s after start, then every 6 h.
- **Status pushed to the renderer:**
  `{ state: 'idle'|'checking'|'available'|'downloading'|'ready'|'none'|'error', version?, percent?, error? }`
- **New setting `autoDownloadUpdates`** (default `true`):
  - On: download runs in the background, then a banner appears: "TidyDesk X is ready — Restart to update".
  - Off: the banner says "TidyDesk X is available — Download". Downloading only happens when the user asks.
- **Install:**
  - "Restart to update" calls `quitAndInstall()` after setting `quitting = true`.
  - A downloaded update also installs when the app quits (`autoInstallOnAppQuit`).
- **Settings → About:** shows the current version, a "Check for updates" button, and the live status.
- **Source:** the existing `publish: github` config. The release workflow already uploads `latest.yml`.

## 4. Exclusions

- **New setting `exclusions: string[]`:** absolute file or folder paths, at most 200.
- **Matching:** `isExcluded(p, list)` is true when `p` equals an entry or lies inside one. The check is case-insensitive and normalises Windows paths.
- **Where it applies:**
  - **Scan time:**
    - junk scan
    - duplicate scan (excluded folders are not entered)
    - large files scan
    - empty folders scan
    - organizer plan (an excluded folder is refused; excluded files inside it are left out)
  - **Action time, in the main process:**
    - `quarantine` skips excluded paths with reason `EXCLUDED`.
    - `applyOrganize` rejects moves from excluded paths.
    - Empty folder removal skips excluded paths.
    - This protects against paths added between scan and action.
- **UI:** a Settings → Exclusions card listing the entries.
  - Buttons: **Add folder…** and **Add file…** (system pickers), and remove per row.
  - The protected system folders are shown as built-in exclusions and can't be removed.

## 5. Large Files finder (new page)

- **Function:** `findLargeFiles(dir, { minSize, limit, signal, onProgress, exclusions })` walks the folder. It returns the `limit` largest files with `size >= minSize`, largest first, using a bounded min-heap.
  - Defaults: `minSize` = 50 MB, `limit` = 200.
- **Page:**
  - Choose a drive (one button per fixed drive) or a folder; drag & drop also works.
  - Progress and Cancel while scanning.
  - Results: one row per file with name, folder, a size bar relative to the largest, type, modified date and Show in folder.
  - Checkboxes, plus **Move selected to Safe Bin** with a confirm dialog. History type is `large-files`.
- **Rules:**
  - Protected folders are refused. A drive root is allowed for this read-only scan, but the system folders inside it are skipped.
  - Moving to the Safe Bin re-checks protected paths and exclusions.
  - Paths must come from the last scan, the same rule as duplicates.

## 6. Empty Folders cleaner (new page)

- **Finding:** `findEmptyFolders(dir, { exclusions, signal })` returns the folders under `dir` that contain no files at any depth.
  - It never includes `dir` itself.
  - It skips hidden or system folders, folders named `.git`, and the Safe Bin.
  - It returns deepest folders first.
- **Removing:** `removeEmptyFolders(paths, history, { dryRun })`:
  - Re-checks each folder is still empty right before removing it with `rmdir`, which only ever removes an empty folder.
  - Records a history entry of type `empty-folders` with status `done`. `moves` stays empty and a new `folders: string[]` field lists what was removed.
- **Restore:** `restoreEmptyFolders(entryId)` recreates the folders with `mkdir -p` and sets status `restored`. It doesn't expire, because nothing is held.
- **Dry run:** the history entry is `simulated` and no folder is removed.
- **Page:** pick or drop a folder, see the list as a tree-like indented list with checkboxes, then **Remove N empty folders**.

## 7. Scheduled auto-clean

- **New settings:**
  - `autoClean: 'off'|'daily'|'weekly'` (default `'off'`)
  - `autoCleanCategories: string[]` (default user-temp, windows-temp, thumbnails, crash-dumps)
  - `lastAutoClean?: number`
- **When it runs:** the scheduler tick runs an auto-clean when all of these hold:
  - the user has acknowledged the first-run notice
  - dry run is off
  - auto-clean is not `off`
  - `now - lastAutoClean >= 24 h` (daily) or `7 days` (weekly)
- **What it does:**
  1. Scans the chosen categories with exclusions applied, then quarantines through the Safe Bin with title "Automatic junk clean" and the 1-hour rule re-applied.
  2. Sets `lastAutoClean`, even when nothing was found, so it doesn't rescan every tick.
  3. If anything moved, shows a Windows notification: "TidyDesk cleaned 1.2 GB — restorable for 5 h". Clicking it opens the Dashboard.
- **Settings UI:** a "Scheduled clean" card with the frequency, category checkboxes and the last run time.

## 8. Organizer options

- **Mode:** a selector on the page with two choices.
  - **By type:** the existing behaviour.
  - **By date:** files go into `YYYY\YYYY-MM` folders based on modified time, for example `2026\2026-10`.
- **Custom categories:**
  - **New setting `organizerCategories?: Record<string, string[]>`.** When it is unset, the built-in table is used.
  - **Editor:** a "Customize categories" dialog on the Organizer page.
    - Rename or add categories, and edit the extension list as comma-separated text.
    - Reset to defaults.
    - Validation:
      - Category names must be valid Windows folder names and unique.
      - An extension may appear in only one category.
      - "Other" is reserved.
- **Undo** works the same for both modes. `createdDirs` now includes nested year and month folders, removed deepest first.

## 9. Drag & drop

- **Reading the path:** the preload exposes `pathForFile(file: File): string` using `webUtils.getPathForFile`.
- **Pages:** Organizer, Duplicates, Large Files and Empty Folders accept a dropped folder.
  - While dragging, a highlighted drop zone says "Drop a folder".
  - The main process checks the path is an existing folder through the normal handlers, with protected-path and exclusion checks.
  - A dropped file, or more than one item, shows "Drop a single folder".
- **Navigation:** document-level `dragover` and `drop` are prevented, so dropping anywhere else does nothing. Main still blocks `will-navigate`.

## 10. Error log & export

- **Log file:** `src/main/logger.ts` writes timestamped lines to `%APPDATA%\TidyDesk\logs\tidydesk.log`.
  - It rotates at 1 MB and keeps 3 files.
  - It records `uncaughtException`, `unhandledRejection`, IPC handler errors, scheduler errors, `render-process-gone`, and renderer `error`/`unhandledrejection` events, which reach main through a new `logRenderer` channel.
  - It never logs file contents, only paths and messages.
- **Settings → Support:**
  - **Open logs folder.**
  - **Export activity as CSV:** a save dialog, then one row per file or move.
    - Columns: `date, action, title, status, dry_run, path, destination, size_bytes, item_state, reason`.
    - Entries without items get one row.
    - It's written as a stream, so large histories don't load into memory at once.

## 11. Data model changes

- **`HistoryType`** adds `'large-files' | 'empty-folders'`.
- **`HistoryEntry`** adds `folders?: string[]`.
- **`Settings`** adds:
  - `autoDownloadUpdates: boolean`
  - `exclusions: string[]`
  - `autoClean: 'off'|'daily'|'weekly'`
  - `autoCleanCategories: string[]`
  - `lastAutoClean?: number`
  - `organizerCategories?: Record<string, string[]>`
  - `organizeMode: 'type'|'date'`

  `sanitizeSettings` validates all of these.
- **`TidyApi`** adds:
  - `largeScan`, `largeCancel`, `largeRemove`
  - `emptyScan`, `emptyRemove`, `emptyRestore`
  - `pickFile`, `pathForFile`
  - `updateCheck`, `updateDownload`, `updateInstall`, `onUpdateStatus`
  - `openLogs`, `exportCsv`, `logRenderer`
  - `drives`, reusing `disk`
- **Sidebar:** adds **Large Files** and **Empty Folders** between Duplicates and Settings.

## 12. Testing

Vitest, against real temporary folders, covering:

- `isExcluded`
- `findLargeFiles`: top-N order, minSize, exclusions, cancel
- `findEmptyFolders`, remove and restore: nested folders, deepest first, re-check-before-remove, dry run, hidden/`.git` skip
- organizer date mode and custom categories: plan and undo round-trip
- scheduler auto-clean due logic: daily, weekly, off, dry run, first-run gate
- the CSV formatter: quoting of commas and quotes in paths
- logger rotation
- the extended `sanitizeSettings`
- the updater state mapping

Each UI feature is also checked in the real app, and the glitch fix with real key presses.

## 13. Release & versioning

- **Version:** **1.0.0**, the first public, stable release. 0.1.0 was never published.
- **From then on, Semantic Versioning (`MAJOR.MINOR.PATCH`):**
  - PATCH (1.0.1) for bug fixes only.
  - MINOR (1.1.0) for new features that don't break existing ones.
  - MAJOR (2.0.0) for breaking changes, such as a settings or history format that old versions can't read, or behaviour users must adapt to.
- **README:** gets the new features, screenshots, an "Updating" section and a "Versioning" section stating this rule.
- **Publishing:** after verification, a `v1.0.0` tag is pushed. GitHub Actions then publishes the Release, which is what installed copies auto-update from.
  - Local 0.1.0 test installs have no updater and need one manual install.
